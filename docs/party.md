# 开黑房间（`/party`）

建房、大厅、聊天、roll 点、分队伍。**房间在服务端**：一条 WebSocket 连到本站的 Worker，
状态放在 Durable Object 里（`src/worker/partyRoom.ts`），浏览器只负责发操作、画快照。
页面本身是 SSR（`prerender = false`），但只为一件事：把「你是谁」按登录态渲染对——
登录状态服务端本来就知道，没必要让已登录的人先看到一个「用 Steam 登录」按钮。

## 为什么从 P2P 改成服务端房间

原来的方案是 Trystero 的 WebRTC 数据通道 + 公共 Nostr 中继信令，房间状态在房主浏览器里。
局域网内两个人没问题，**跨网络就靠打洞**，而国内手机流量（4G/5G）大量是对称 NAT，打不出洞；
于是又加 TURN 中转，TURN 还要云安全组放行 UDP——整条链上任何一环坏了，页面上的表现都只有
一句话：**「房间里没人」**。实测过的每一环都足以让手机进不了房：

| 环节 | 实测结果 |
| --- | --- |
| 默认 STUN（`stun*.l.google.com` + Cloudflare） | 境内部分网络拿不到 srflx 候选；同一个 WiFi 靠 host 候选照样能连，于是症状是「同一个 WiFi 行、跨网络不行」 |
| 换成境内 STUN（miwifi / B 站 / 芒果） | 本机三个都能回 srflx，但对方的网络未必，只能改善不能保证 |
| 自建 coturn | 服务本身是通的（无凭据 401、带凭据能分配、中继端口在段内），但**入站 UDP 被云安全组丢包**：德国、西班牙、荷兰、波兰、乌克兰五个外部节点打 `UDP 3478` 全部超时 |
| 公共 Nostr 中继 | 常年有几个连不上（`nos.lol` 是常客） |

所以现在把权威挪到服务端：客户端与房间之间就是**一条 WebSocket**，不再有 NAT、STUN、TURN、
公共中继、候选线路。代价是房间状态存在服务端，见下文「已知的取舍」。

| 文件 | 职责 |
| --- | --- |
| `src/pages/party.astro` | 页面骨架（身份按会话渲染、设置区 / 房间区），不写业务逻辑 |
| `src/scripts/partyRoom.ts` | 客户端：两条 WebSocket（大厅 / 房间）、渲染、事件、断线重连 |
| `src/lib/partyProtocol.ts` | 消息协议与解析（**信任边界**：来自别人浏览器的输入一律先验形状） |
| `src/lib/partyLogic.ts` | 成员/队伍/roll 的**纯状态变换**，不碰 DOM 也不碰网络 |
| `src/worker/index.ts` | Worker 入口：在 Astro 的 handler 外面包一层，把 `/api/party/*` 转到 DO |
| `src/worker/partyRoom.ts` | 两个 Durable Object：`PartyRoom`（一个房间一个）与 `PartyLobby`（大厅列表） |
| `scripts/partyLogic.check.ts` | 分队 / roll 那层的自检（队伍重排最容易写错） |
| `scripts/partyProtocol.check.ts` | 协议解析的自检：该收的收、该拒的拒 |
| `scripts/steamId.check.ts` | 手填 Steam ID 的解析自检（错一位就查到别人头上） |
| `scripts/partyVisibility.check.ts` | 静态可见性自检：标记里不许有脚本摘不掉的隐藏手法 |
| `scripts/partyDrag.check.ts` | 拖拽归队的自检：拖拽写错全是静默失效，见下文「归队有两条路」 |

**显隐一律走 `setVisible()`**（同时摘 `hidden` 属性、写内联 `display`）。标记里
**不要**用 `hidden` 属性或独立的 `hidden` 类来藏要切换的元素：Tailwind v4 的 preflight 是
`[hidden] { display: none !important }`，`hidden` 类也在 utility 层，两者都会让元素
**永远露不出来**——房间区、提示条、Steam ID 折叠块都这么栽过一次，症状是「页面上什么都没有，
也不报错」。最后那条自检就是为了挡住这一类。

纯逻辑单独抽出来的理由很实际：分队规则里有几个必须收敛的分支（每队上限调小时超员的人
去哪、房主手动加的队会不会被自动分队顺手删掉、最后一个队能不能删），脱离浏览器才验得动：

```sh
pnpm check   # 协议 + 队伍逻辑 + Steam ID 解析 + 拖拽规则，纯 node，不需要浏览器
```

## 「我是谁」的三种来源

| 来源 | 拿到什么 | 能不能证明身份 |
| --- | --- | --- |
| Steam 登录（OpenID） | 昵称 + 头像，由服务端回 Steam 反查后写进签名 Cookie | **能**，这是唯一可信的来源 |
| 手填 Steam ID | 昵称 + 头像，`/api/steam/profile` 转成 accountId 后向 STRATZ 查 | **不能**，谁都能查任意账号 |
| 什么都不填 | 自己打的昵称 + 首字母头像 | 不能 |

手填那条路由是**公网可调用**的：每次未命中都会消耗一次 STRATZ 额度，所以只取了
`steamAccount { name avatar }` 两个字段（不去拉 `loadPlayerProfile` 那份带 60 个英雄的
大查询）、结果缓存 6 小时，并且复用了 `gql()` 里的串行限速。没配 `STRATZ_TOKEN` 时
这条功能返回 503 并提示直接填昵称，不是报错。

解析支持 SteamID64、账号 id（Steam 好友码就是它）、`STEAM_X:Y:Z`、`[U:1:Z]` 与
`/profiles/<id>` 链接；**`/id/<自定义短名>` 不支持**——换算它要 Steam Web API Key，
而本站登录只用 OpenID，为一个头像再引入一个密钥不划算。


## 协议与谁说了算

- **服务端是唯一权威。** 谁在房里、队伍怎么分、roll 出几点、谁能改什么，全在 Durable Object
  里算（用的还是 `partyLogic.ts`，所以那层自检一条都不用改）。浏览器只发消息、只画快照，
  于是「房主本地先改再广播」那套、以及丢迟到快照的判断一起消失了。
- **密码在服务端校验。** 房间里存的是密码的 SHA-256，进房时比对；对了才写进名册。
  `bad-password` / `room-not-found` 是服务端明确回的 code，页面照着说人话。
- **重连靠 clientId。** 客户端把它存在 sessionStorage（刷新不变、两个标签页互不影响），
  重连时带上同一个 id：服务端认得出是同一个人，名册、队伍位置、roll 结果原地保留，
  房主刷新也不会把房间交出去。老方案里「房主刷新后 peerId 变了」是最难缠的一段，现在连同
  那段代码一起没了。
- **房主可以换人。** 房主退出后房间交给名册里最早加入的那位（记一条系统消息）；房间空了则
  保留 10 分钟（`EMPTY_ROOM_TTL_MS`），房主刷新回来还是同一个房间。
- **房间与聊天存在 DO 里**（`state.storage`）。WebSocket Hibernation 下进程会被回收，
  所以状态必须落盘；聊天 `CHAT_KEEP` 条封顶，房间空置 10 分钟后连聊天一起删。
- **一条连接一把闸。** 单连接 10 秒内超过 60 条消息直接断开；`/api/party/rooms` 的 POST 是
  房间内部的上报通道，外部只允许 GET。

## 连不上 / 进不去时的提示

传输只剩一条 WebSocket，失败面比 P2P 小得多，但每种情况仍然分别说清楚：

| 现象 | 原因 | 页面上的提示 |
| --- | --- | --- |
| 顶栏一直「正在连接…」 | 网络把 WebSocket 拦了（公司网 / 校园网 / 部分公共 WiFi） | 大厅列表空、状态条不绿；进房时 12 秒后提示「换个网络再试」 |
| 「密码不对」 | 房间密码与房主设的不一致 | 直说密码不对，并提醒回去问房主 |
| 「房间不存在了」 | 房间码抄错，或房主关掉后已超过 10 分钟 | 直说房间没了 |
| 中途「正在重连…」 | 手机切前后台、地铁断网这类瞬时断连 | 自动退避重连，回来还是同一个人，状态不丢 |

## 已知的取舍

- **昵称是自报的。** 登录 Steam 的人由服务端给出昵称和头像，但房间里它仍无法被他人验证——
  知道房间密码的人可以自称任何名字。要堵住得让服务端签发一张可离线验签的票据
  （Ed25519 + 公钥），目前没做，开黑场景够用。
- **房间不设人数上限。** 现在一条消息要推给房间里所有人，真正的上限是 DO 的广播开销与
  浏览器渲染，几十人以上就该分页或增量推了。在应用层卡一个数字只会挡自己人（开黑本来就要
  5v5 往上），要加也在 `upsertMember` 那一层加。
- **房间状态属于服务端。** DO 里存的是房间与聊天（`state.storage`），关掉页面房间还能撑
  10 分钟；也就是说「本站不存房间」这句宣传语不再成立，改成了「服务端只存房间状态与聊天，
  空置 10 分钟即删」。免费版的 DO 额度是 10 万请求/天 + 13,000 GB-s/天，WebSocket 消息按
  请求计——开黑场景离上限很远，但心里要有这笔账。
- **队伍分配区有两种全屏，是两件事**（工具栏上两个按钮）：**浏览器全屏**走 Fullscreen API，
  浏览器收起地址栏与标签页，和 F11 一样；**网页全屏**是纯 CSS 固定定位，在当前页面里把这块
  盖满视口，浏览器界面照旧（它同时锁住 body 滚动，否则滚轮会穿透到后面的页面）。两者互斥。
  都不做「另开一个页面」——两条 WebSocket 与页面生命周期绑在一起，另开页面就是另一个人
  （clientId 存在 sessionStorage，按标签页算）。不支持元素级全屏的浏览器（如 iPad Safari）上，
  浏览器全屏自动退回网页全屏。
- **大厅只有一个 DO。** 房间在创建/增减人/关闭时通过内部 POST 上报，大厅再把整张列表推给
  所有订阅者。房间多了以后这里是单点，不过列表很小、又不是高频，够用很久。
- **归队有两条路，权限一样。** 每张成员卡左边有个 ⋮⋮ 手柄，鼠标用户可以把它拖到任意队伍卡片上
  （拖回空闲池就是退队）；右边仍然保留下拉框，因为**拖拽在触屏和键盘上都没有等价操作**，而下拉
  天然三端可用（同「分屏直播」里「拖拽必须有等价操作」的结论）。两条路都走 `moveMemberTo()`，
  房主能挪任何人、其他人只能挪自己。`draggable` 只挂在那两个点上、不挂整张卡——卡里嵌着那个
  `<select>`，祖先带 `draggable` 之后它在部分浏览器里点不动。几个静默坑（`dragover` 不
  `preventDefault` 就永远不触发 `drop`、Firefox 不 `setData` 就不开始拖、重建队伍区必须
  `clearDrag()`）都固化在 `scripts/partyDrag.check.ts` 里。
- **`/party` 的客户端包比原来小了一大截**：Trystero 与 Nostr 客户端（约 30 KB gzip）连同
  STUN/TURN 配置一起删掉了，只剩下页面自身的逻辑与 `partyLogic` 的状态变换。
