# 访问统计

## 它要回答的问题

只有一句：**值不值得做 PWA**。

想清楚这件事之后再决定不做的可能性更大：这个站的核心价值是新鲜度（每 30 分钟一轮重建，见
`docs/deploy.md`），而 PWA 的机制是「把东西留在客户端」。真按常见教程用
stale-while-revalidate 缓存 HTML，读者就会看到上一轮的赛程——那正是当初把重建从 GitHub 的
尽力而为换成 Cloudflare 准点 cron 想要避免的事。剩下真正能拿到的收益是「装到桌面」与
「弱网下重复访问更快」，而 `/_astro/*` 已经被适配器注入的 `_headers` 给了
`public, max-age=31536000, immutable`（构建产物里的 `dist/client/_headers`）。

所以判断的落脚点是**有没有稳定的回访**：回访多，装到桌面才有意义；都是搜索落地的一次性访问，
那点时间投到能被搜到的内容上更划算。

## 用什么统计

Cloudflare Web Analytics：无 Cookie、不采指纹（不需要隐私弹窗）、与站点同属一个厂商
（国内可达性与站点本身一致）、只有一个 `defer` 脚本、不阻塞渲染。

**怎么开**：

1. Cloudflare 面板 → **Web Analytics → 添加站点**，填 `dota2.hiwenbin.com`，拿到 beacon token；
2. 把它填进 `src/data/site.ts` 的 `ANALYTICS.cfBeaconToken`（是公开值，本来就出现在 HTML 里）；
3. 重新构建并发布。

配之前**一行脚本都不输出**，所以「没配」等于「没有统计」，不会静默地替别人打点。

## 看哪几个数

| 指标 | 怎么读 |
| --- | --- |
| **访问次数 ÷ 独立访客** | 回访的代理指标。≈1 表示基本都是「搜一次、看一页就走」；>1.5 表示有明显回访；>2 说明有一批人天天来 |
| 移动端占比 | 决定「装到桌面」的池子有多大——桌面为主的话 PWA 更没意义 |
| 热门落地页 | 看流量是不是集中在英雄页/赛程页这类搜索长尾（是 → 一次性访问为主） |

它不直接给「新老访客」拆分，所以要靠上面第一个比值。**如果国内拿到的数据太薄**（脚本被拦、
或样本少到看不出趋势），备选是百度统计——它直接给「新访客 / 老访客」，代价是第三方脚本、
Cookie 与隐私说明都要跟着处理。

## 什么条件下做 PWA

按上面的数，两周之后：

- **回访比值 > 1.5 且移动端占多数** → 做最小版：manifest + 192/512 图标 + `theme-color`，
  外加**只缓存资产与字体、不拦导航**的 Service Worker（导航仍然 network-first，绝不
  precache HTML）；
- **回访比值 ≈ 1、以搜索落地为主** → 不做，把时间投到内容页；
- **两者之间** → 只加 manifest + 图标（不写 SW）：半小时、零风险，iOS 上就有正经图标与全屏
  打开，代价是 Android 的安装提示可能不出现。

## 实现上的两个细节

- **只在生产域名打点**：`Layout.astro` 里比对 `Astro.site.host` 与 `Astro.url.host`，
  `astro dev` / `astro preview` 落在 localhost 时不会把本地刷新算进去。
- **`/party` 上不打点**：房间码在 URL 的 `#` 片段里（`src/scripts/partyRoom.ts` 的
  `codeFromHash`），邀请链接本身就是凭码进房的凭证，不该出现在第三方的报表里。
