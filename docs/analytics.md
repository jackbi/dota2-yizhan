# 访问统计

## 它要回答的问题

只有一句：**值不值得做 PWA**。

想清楚这件事之后再决定不做的可能性更大：这个站的核心价值是新鲜度（每 30 分钟一轮重建，见
`docs/deploy.md`），而 PWA 的机制是「把东西留在客户端」。真按常见教程用
stale-while-revalidate 缓存 HTML，读者就会看到上一轮的赛程——那正是当初把重建从 GitHub 的
尽力而为换成 Cloudflare 准点 cron 想要避免的事。剩下真正能拿到的收益是「装到桌面」与
「弱网下重复访问更快」，而 `/_astro/*` 已经被适配器注入的 `_headers` 给了
`public, max-age=31536000, immutable`（构建产物里的 `dist/client/_headers`）。

所以判断的落脚点是**有没有稳定的回访**：回访多，装到桌面才有意义；都是搜索落地的一次性访问，
那点时间投到能被搜到的内容上更划算。

## 用什么统计

Cloudflare Web Analytics：无 Cookie、不采指纹（不需要隐私弹窗）、与站点同属一个厂商
（国内可达性与站点本身一致）、只有一个 `defer` 脚本、不阻塞渲染。

**先查再配**：这个账号的主域（`hiwenbin.com`）**已经开了自动注入**，面板里能直接看到
`dota2.hiwenbin.com/...` 的页面浏览量——实测这套自动注入对「Worker + 自定义域名」的部署是生效的。
所以 `ANALYTICS.cfBeaconToken` **保持留空**：

- **两套 beacon 会各记一次**，页面浏览量与访问量会翻倍，等于把这份数据毁了；
- 留空时 Layout 里一行脚本都不输出（实测 1033 个页面里 0 个带脚本），自动那份照常工作。

只有当站点搬到不走 Cloudflare 代理的地方（或另挂一个域），自动注入不再生效时，才去
面板 **Web Analytics → 添加站点** 拿 token 填进 `src/data/site.ts`。它是公开值（本来就出现在
HTML 里），所以进仓库没问题——和 Layout 里那几个搜索引擎验证标签是一类东西。

## 看哪几个数

先说清楚**它给不了什么**：官方指标只有 Page load time、Core Web Vitals、Visits、Page views，
**没有独立访客，也没有新老访客**。所以「回访占比」只能靠三个替代指标拼出来：

| 替代指标 | 怎么读 |
| --- | --- |
| **访问量在时间上的稳定性**（切到过去 28 天） | 每天都有人来、比赛日有规律峰 → 有固定受众；只在新内容推送后的几小时尖峰、之后归零 → 搜索落地型 |
| **页面浏览量 ÷ 访问量** | 官方对 visit 的定义是「从站外或直接进入的那一次」，站内后续跳转只计 page view。所以这个比值 = 平均每次进来翻几页：>3 说明进来的人愿意往里走，≈1 说明看一眼就走 |
| **URL 维度里有没有长期占位的核心页** | 英雄页、赛程页、资讯页每天都有稳定量 → 更像固定受众；量全压在某几篇新内容上 → 一次性访问 |

如果面板里能翻到来源 / 引荐维度，**直接访问的占比**是最接近「回访」的一个数（老读者多半是
收藏或直接输域名进来）；这一版界面里只看到 URL / 浏览器 / 操作系统 / 国家 / 元素五个维度，
所以按上表三条来读。

**如果国内拿到的数据太薄**（样本少到看不出趋势），备选是百度统计——它直接给「新访客 / 老访客」，
代价是第三方脚本、Cookie 与隐私说明都要跟着处理。

## 什么条件下做 PWA

按上面的数，两周之后：

- **28 天里访问量每天都有底、页面浏览量 ÷ 访问量 > 3、核心页长期占位** → 说明有一批固定受众，
  做最小版：manifest + 192/512 图标 + `theme-color`，外加**只缓存资产与字体、不拦导航**的
  Service Worker（导航仍然 network-first，绝不 precache HTML）；
- **流量只跟着内容更新尖峰、之后归零** → 搜索落地型，不做，把时间投到内容页；
- **两者之间** → 只加 manifest + 图标（不写 SW）：半小时、零风险，iOS 上就有正经图标与全屏
  打开，代价是 Android 的安装提示可能不出现。

## 实现上的两个细节

- **只在生产域名打点**：`Layout.astro` 里比对 `Astro.site.host` 与 `Astro.url.host`，
  `astro dev` / `astro preview` 落在 localhost 时不会把本地刷新算进去。
- **`/party` 上不打点**：房间码在 URL 的 `#` 片段里（`src/scripts/partyRoom.ts` 的
  `codeFromHash`），不该出现在任何报表里。实测 Cloudflare 的 beacon **只读
  `location.pathname` / `location.search`，不读 `location.hash`**，所以自动注入那份也不会
  带上房间码；`Layout` 里对 `/party` 的排除是留给「自己注入」那条路的保险。
